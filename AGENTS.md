# go-perplexity

Unofficial Go client for the Perplexity REST API, generated from Perplexity's OpenAPI document. If you only want to use the client from an agent, read [.agents/skills/go-perplexity/SKILL.md](.agents/skills/go-perplexity/SKILL.md) instead; this file is about changing the code.

## Architecture

`make generate` runs `go generate ./...`, which follows `gen.go`:

1. `scripts/fetch-spec.sh` downloads `https://docs.perplexity.ai/openapi.json` into the gitignored `api/openapi.json`.
2. No patch scripts: the current spec generates as is. If a future spec breaks oapi-codegen, add a jq patch script under `scripts/` and a `go:generate` line for it in `gen.go`.
3. oapi-codegen (`go tool oapi-codegen`) reads `config.yaml` and writes `client.gen.go`: models, `Client` and `ClientWithResponses`.

## Stack

- Go 1.26.9, one package `perplexity` at the module root.
- oapi-codegen v2 as a Go tool dependency, `github.com/oapi-codegen/runtime` at runtime.
- Tests: `testify` and `net/http/httptest`.

## Layout

- `gen.go`: package doc and the `go:generate` steps.
- `config.yaml`: oapi-codegen config (`number` to `float64`).
- `client.gen.go`: generated, committed.
- `client_test.go`, `example_test.go`: hand-written tests and the README example.
- `scripts/`: spec fetch, lint and security scan scripts the Makefile runs.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- Several operation IDs are derived from routes, so method names are long (`ChatCompletionsChatCompletionsPost`, `EmbeddingsV1EmbeddingsPost`). A spec update that renames an operation ID renames the method; check the README, the skill and the tests after `make generate`.
- `ListModelsResponse` is a schema in the spec, so the list models response wrapper is `ListModelsResponse2`.
- Skill create and update take a raw body only (`CreateSkillWithBody`, `UpdateSkillWithBody`).
- CI does not run `make generate`, because the spec changes upstream. Regenerate locally and commit the result.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
